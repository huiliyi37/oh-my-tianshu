# Agent Note：TUI 常驻待办面板

Status: proposed

[English](2026-08-23-tui-todos-panel.md) | 中文

## 问题

`todo_write` 记录模型的计划，数据也已经通过 [`todos` 投影键](../../../../packages/todo/tool-todo/README.md)从会话日志投影出来。用户缺的是随时可见的一瞥：目前列表只在按需打开时出现——`/status` 面板的任务段与 `/tasks` 窗格都渲染它，但都要用户主动打开。Claude Code 给它的 TodoWrite 工具配了一个工作期间常驻可见的待办面板。此处的真实增量是一张紧凑的常驻卡片加 `/todos` 开关，而不是首次提供待办视图。

## 提案

在 [`packages/tui/tui`](../../../../packages/tui/tui/README.md) 内做纯 TUI 改动：把 `todos` 会话投影渲染为活动带里的紧凑常驻卡片，并注册 `/todos` 命令切换显隐。无 harness 改动、无新包、无新事件词汇表。TUI 已经订阅该投影并缓存其值（`app.ts` `taskItems`），所以这张卡片增加的是渲染器与开关，而不是数据管线。

### 数据源与回合边界

该投影的 fold 语义是：`todo/write` 全值替换列表；`turn/start` 把 fold 重置为 `null`；`turn/end` 保留已完成的清单可见。因此卡片不能把 `null` 当作"隐藏"：控制器缓存最近的非 null 快照，回合边界重置后卡片继续显示上一回合的列表并带过期标记，直到下一次 `todo/write` 替换它。`null` 只在会话首次写入前隐藏卡片，显式的空写入渲染全部完成态。

### 渲染面

新纯渲染模块 `src/format/todos-panel.ts` 遵循工具渲染意图约定：面板参数进、行文本出，无模型交互。控制器在活动带顶部绘制单行卡片：待办与完成计数、当前进行中项、过期标记，以及展开/收起状态，像既有 live 卡片一样限高。

### 表面分工

`/status` 保留其按需的完整面板，以及任务段刻意把 `null` 当占位符的合并语义；`/tasks` 继续负责后台任务执行。新卡片是唯一区分 `null`（从未写入）与空列表（全部完成）的表面，并独占常驻、可切换的呈现。其他表面不变。

### 命令面

`/todos`（无参）切换卡片显隐，注册进 TUI 内置斜杠命令注册表，因此出现在 `/help` 与命令面板（Ctrl+P）中。它不是键盘绑定，因此没有 `KEYMAP_ENTRIES` 条目——那是一张只收录键盘快捷键的表。

## 备选方案

### 为什么不扩展 `/status`？

状态面板是按需打开、全宽的；常驻卡片必须小巧、始终可见、一眼可扫。合并两种需求要么撑大状态面板，要么把卡片藏进一个必须主动打开的面板后面。

### 为什么不做 harness 级待办面板服务？

投影已经存在，卡片只是展示；服务会重复日志已经提供的折叠，并为单个适配器加宽 harness。

### 为什么不并入 `/tasks`？

`/tasks` 负责后台任务执行；待办是模型的计划状态。合并两个领域会搞乱两个面。

### 为什么不开新包？

改动只触及 TUI 渲染及其测试；新包不携带独立能力，会违反当前所有者要求。

## 验收标准

- 单测覆盖渲染函数各状态（隐藏、待办中、进行中、全部完成、过期、超限截断），以及控制器在 `todo/write` → `turn/start` → `todo/write` 投影序列中的缓存行为。
- keyless 快照驱动一次 `todo_write` 工具调用，并断言写入前后的卡片行，包括回合重置后的过期标记。
- bundle-patch spec 断言 `/todos` 在斜杠注册表中的注册及其 `/help` 列表；不修改 `KEYMAP_ENTRIES`。
- `/status` 任务段保持现有 `null` 当占位符的行为，由既有测试保持绿色证明。
- 无新持久事件、无新包；README 与本笔记随落地提交移入 `implemented/`。

## 风险

- 回合边界重置后，缓存列表可能属于上一回合；过期标记让这一点诚实可见，显式空写入仍清为全部完成态。
- `null` 与空列表是卡片必须区分的语义，而 `/status` 合并二者；共用渲染器会重新引入合并，所以卡片保持自己的渲染路径。
- 切换是逐会话的 UI 状态，不持久化；重开的会话从隐藏开始。
- 卡片与活动带共享高度预算；限高与收起状态约束成本，长列表显示计数加当前项而非全部行。

## 实现修订（2026-08-23）

已在工作区实现于 `packages/tui/tui`，含以下修正：

- 原前提夸大了空白：`/status` 与 `/tasks` 已渲染 todos 投影。实际落地的是紧凑摘要卡（计数+当前项）与 `/todos` 开关，而非首个视图。
- 投影在每个 `turn/start` 重置为 null；面板改读「保留快照」（只吸收非空值），可见清单跨回合黏滞、不随回合边界闪烁消失。
- `/todos` 位于斜杠注册表、`/help` 与命令面板——keymap 面板只列键盘快捷键，原验收标准指错了表面。
- 新渲染器保持 null 与 `[]` 可区分（空态 vs 全部完成），不同于 `/status` 的刻意合并。
- PTY keyless 快照延后；面板行经 app.spec 的真实渲染管线断言。
