# Agent Note: 上游 v0.1.1-rc.1 按需移植——授权链、视觉模型与运行时修复

Status: implemented

[English](2026-08-21-upstream-v0.1.1-rc.1-port.md) | 中文

## 问题

上游 `deepseek-harness` 发布 `dsh-v0.1.1-rc.1`（rc.8 分叉基线之后 111 个非 merge 提交）。本仓库的既定立场是按需移植而非追踪上游（见[上游 parity note](2026-08-16-upstream-subsystem-port-parity.md)）：按本地消费方所需取入，并按本地分叉适配。本轮增量中有两组直接补上用户已声明的缺口——供应商/密钥引导与视觉模型——另有若干针对本地携带子系统的真实运行时修复。

## 决定

按依赖序移植，每组测试全绿再进下一组：

- **凭证/授权链**（上游 `86a9f8c862`…`9eaaeaeb96`，取 rc.1 终态）：`atomic-write` 增加 `waitMs` 与 Windows EPERM 锁竞争识别；`dsh-credentials` 演进为 `CredentialProvider`，新增持久记录半面（`CredentialKey` brand、`ApiKeyRecord | GrantRecord`、`modifyRecord` 为跨进程锁下的唯一写路径），事件拆分为 `reference-updated`/`record-updated`；`dsh-credentials-local` 持久化 versioned 两节文档，写路径 30 秒锁等待、api-key 准入校验、boot 时迁移 pre-release 平铺文档（对既有 `~/.dsh-tianshu` 安装是必需品）；新包 `dsh-authorization`（流程注册表、每键单次尝试、settled 事件）挂载进 `bundle/base`；`dsh-llm-pi-ai` 新增 `auth.ts`/`login.ts`——pi-ai 凭据存储覆于 harness 记录之上，登录流程经可选 `authorization` seam 注册，保留本地 `environmentOf` 与 `routeAuth` 分叉。
- **视觉模型**（`4fa38d6a23` + 评审修复）：`deepseek-v4-flash-vision-exp` 进入默认目录——以本仓库的 `supportsVision` 词汇表达，而非上游的 `inputModalities`：本地视觉管线（目录 → modelInfo → 能力门）本就运行在该字段上。
- **运行时修复**：subagent continuation 清理（dispose-then-delete 次序、聚合成 AggregateError 重抛）与 timing schema 的 `transform` 规整；sandbox-local 的 bwrap 增加 `--unshare-pid`、探针复用 `bwrapProfileArgs`，关闭 procfs 根逃逸；ui-conversation 的 turn-error 删除重试链抑制，同轮重试耗尽后终态错误照常渲染。
- **Web client 波次**（上游 `795d36d68f`、`b2c9c3ce37`、`99aad0ebcd`、`a4da0f40d5`+`fa2ce12162`、`000ab970f3`+`c9ce61136d`、`b03b1f2e7b` 仅 (a) 半、`9616790b6c`+`7260f4cf64`、`d53292b30a` 的 render-only 原则）：composer 编辑区间管线（beforeinput 捕获 → `setDraft(text, range)`）、引用装饰按草稿序取 key、cache-hit 百分比按最小可分辨精度显示、表格按列数定尺寸且滚动条 hover 才出现、permission 预设本地化文案、多行问答六行封顶、workspace 树当前 blank 行渲染期置顶（本地无持久化 order account——置顶落在派生层）。

有意跳过：frontend-static 的 SPA-fallback→404 翻转（本地 web shell 的既定契约是 fallback；上游的 404 与其自身 web 架构演进配套）、i18n 链接/CI/docs 站波次（本地体系已分叉）、官方快照夹具重构、permission-presets 的 (b) blank 默认刷新与 subagent 头部切换器（适配较大或属新能力——另起一轮）、session-projection 的 state/view refactor（对本地已分叉的消费面动 seam 契约——需要独立预研）。

## 否决的替代方案

**cherry-pick 上游提交。** 不可行——两侧历史没有 merge base；所有移植按内容进行，逐文件应用 scope 改名与本地分叉适配。

**采用上游的 `inputModalities` 目录形状。** 否决：本地 `supportsVision` 门已贯通目录 → 解析 → 请求拒绝；换词汇只会无谓翻动管线，零行为收益。

**authorization 只挂 TUI profile。** 按决定挂 `bundle/base`，全 profile 获得该 seam；llm-pi-ai 对它是可选消费，无登录面的组合不受影响。

## 后果

既有平铺布局的 `~/.dsh-tianshu/.credentials.yaml` 在 boot 时于写锁内迁移；识别不了的布局保持 loud 拒绝。`credentials/updated` 已改名——消费方（apiproxy、TUI 轮询）在同一轮更新。TUI `/login` 面板现在可以建立在 `authorization.list/begin` 之上（seam 已识别，接线留待后续）。Web e2e 快照按 replay 更新；浏览器实测归 CI。
