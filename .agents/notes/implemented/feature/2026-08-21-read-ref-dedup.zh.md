# Agent Note：read-ref 去重

Status: implemented

[English](2026-08-21-read-ref-dedup.md) | 中文

## 问题

模型会在同一会话里重读未变更的文件（验证循环、编辑后确认）。每次重读都往消息历史追加又一份完整内容——上游天枢的实测把大部分 cacheCreate token 归因于正是这种轮内工具结果增长：后缀未缓存，同样的内容在每个请求里被重复付费。

## 决策

`dsh-tool-fs` 的 `read` 在以下条件全部成立时返回一行 `[read-ref]` 引用而非全文：同会话、同解析目标、同 stat 版本令牌（后端的新鲜度身份——任何编辑都会改变它）、同窗口（offset/limit；focus 读取永不引用）、文件大小 ≥ `readRefThresholdBytes`（缺省 2048，`0` 关闭）。引用文本告知模型内容已在会话里，需要别的部分请换窗口/focus。

防循环：一个状态的引用只服务一次——引用之后仍坚持重读的那次返回真内容（模型证明它要的是字节本身），随后的全量读重置状态，再之后的未变更读又会引用。状态放在以会话对象为键的 `WeakMap` 里，随会话消亡；引用结果照发 `fs/observed`（引用对策略层仍是一次读取观察）。契约双向成立：引用文本就是入日志的模型可见结果，完整内容在更早的已入日志读取中可恢复。

## 验证

真文件系统测试（`tools.spec`、`fsHarness`）：首读服务内容、二读服务引用、坚持的第三读降级为内容、文件改动失效（版本令牌变化）、不同 offset 服务内容、低于阈值的文件永不引用、大文件的阈值开启行为复核。
