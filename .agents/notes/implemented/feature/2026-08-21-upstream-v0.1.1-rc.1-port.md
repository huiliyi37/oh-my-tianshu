# Agent Note: Upstream v0.1.1-rc.1 on-demand port — auth chain, vision model, runtime fixes

Status: implemented

English | [中文](2026-08-21-upstream-v0.1.1-rc.1-port.zh.md)

## Problem

Upstream `deepseek-harness` released `dsh-v0.1.1-rc.1` (111 non-merge commits past the rc.8 fork base). The fork's standing policy is on-demand porting, not tracking ([upstream parity note](2026-08-16-upstream-subsystem-port-parity.md)): take what local consumers need, adapted to local divergence. Two increments answer gaps the user had already declared — supplier/key guidance and a vision model — and several are real runtime fixes for subsystems the fork carries.

## Decision

Ported, by dependency order, with each group's tests green before the next:

- **Credential/authorization chain** (upstream `86a9f8c862`…`9eaaeaeb96`, taken at the rc.1 end state): `atomic-write` gains `waitMs` + Windows EPERM lock-contention detection; `dsh-credentials` becomes `CredentialProvider` with a durable record half (`CredentialKey` brand, `ApiKeyRecord | GrantRecord`, `modifyRecord` as the single write path under a cross-process lock) and the event split `reference-updated`/`record-updated`; `dsh-credentials-local` persists a versioned two-section document with a 30s writer-lock wait, api-key admission checks, and a boot-time migration of the pre-release flat document (mandatory for existing `~/.dsh-tianshu` installs); new package `dsh-authorization` (flow registry, one attempt per key, settled event) mounts in `bundle/base`; `dsh-llm-pi-ai` gains `auth.ts`/`login.ts` — pi-ai's credential store overlaid on harness records, flows registered through the optional `authorization` seam, local `environmentOf` and `routeAuth` divergence kept.
- **Vision model** (`4fa38d6a23` + review fix): `deepseek-v4-flash-vision-exp` joins the default catalog — expressed in the fork's `supportsVision` vocabulary, not upstream's `inputModalities`, because the fork's vision pipeline (catalog → modelInfo → capability gate) already runs on that field.
- **Runtime fixes**: subagent continuation cleanup (dispose-then-delete ordering, aggregated rethrow) and timing-schema `transform` normalization; sandbox-local bwrap gains `--unshare-pid` with the probe reusing `bwrapProfileArgs`, closing the procfs-root escape; ui-conversation turn-error drops the retry-chain suppression so an exhausted same-turn retry still renders its terminal error.
- **Web client wave** (upstream `795d36d68f`, `b2c9c3ce37`, `99aad0ebcd`, `a4da0f40d5`+`fa2ce12162`, `000ab970f3`+`c9ce61136d`, `b03b1f2e7b` (a) only, `9616790b6c`+`7260f4cf64`, `d53292b30a` render-only principle): composer edit-range plumbing (beforeinput capture → `setDraft(text, range)`), reference decorations keyed by draft order, cache-hit percent with minimal distinguishable precision, column-count table sizing with hover-revealed scrollbars, localized permission preset labels, multiline question answers capped at six lines, and the current blank session pinned at render time in the workspace tree (no persistent order account exists locally — the pin lives in the derivation layer).

Skipped deliberately: frontend-static's SPA-fallback→404 flip (the local web shell's locked contract is the fallback; upstream's 404 pairs with its own web re-architecture), the i18n-link/CI/docs-site waves (local systems diverge), the official snapshot-fixture rework, `permission-presets` (b) blank-session default refresh and the subagent header switcher (larger adaptation or new capability — separate round), and the session-projection state/view refactor (seam-contract change against a diverged local consumer surface — needs its own investigation).

## Alternatives considered

**Cherry-pick the upstream commits.** Impossible — the histories do not share a merge base; every port is by content, with scope renames and local-divergence adaptation applied per file.

**Take upstream's `inputModalities` catalog shape.** Rejected: the fork's `supportsVision` gate already flows catalog → resolve → request rejection; swapping vocabularies would churn the pipeline for zero behavior gain.

**Mount authorization only in the TUI profile.** The brief chose `bundle/base` so every profile gains the seam; llm-pi-ai consumes it optionally, so compositions without a login surface are unaffected.

## Consequences

Existing flat `~/.dsh-tianshu/.credentials.yaml` files migrate at boot inside the writer lock; unrecognized layouts still fail loud. `credentials/updated` is renamed — consumers (apiproxy, TUI polling) were updated in the same pass. The TUI `/login` surface can now build on `authorization.list/begin` (seam identified, wiring deferred). Web e2e snapshots were updated for replay; browser verification is CI's job.
