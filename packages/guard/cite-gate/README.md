# @huiliyi37/dsh-cite-gate

English | [中文](README.zh.md)

An advisory citation gate — not a model-facing tool. It never appears in the tool list, never vetoes or rewrites a call, and adds exactly one behavior: after each assembled assistant message it folds a short notice into the next step when the message cites something it cannot back:

1. **fabricated upgrade-card IDs** — an ID like `DSH-0.1.2-A9-99` that is absent from the compiled card vocabulary of [dsh-plugin-upgrade-skill](https://github.com/oh-my-dsh/dsh-plugin-upgrade-skill) (curated version cards + corridor rollup). Fabricating an authoritative-looking card is the most common hallucination shape in migration answers;
2. **legacy error codes** — a 0.1.1-era hyphenated code (`cancelled`, `internal`, `session-not-found`, …) that alpha.2 renamed with a namespace (`gateway/cancelled`, `session/not-found`, …). Branching on old codes never matches on the new host;
3. (opt-in, off by default) **unknown namespaced codes** not in the curated alpha.2 list;
4. **read-before-cite** — a file path the session never actually read or wrote. Citing a path you never opened is the other classic hallucination shape.

The decision stays entirely with the model; every notice is advisory and budgeted (3 per turn by default, deduplicated per session).

## Motivation (benchmark calibration, 2026-09-01)

The with/without-skill calibration runs for the upgrade-skill benchmark showed the pattern this guard closes: closed-book agents reasoned at 60–90% content quality but scored 0% on repository vocabulary — and their answers contained fabricated cards (e.g. an "apply lifecycle replacement" that never existed) presented as confident findings. The guard turns that failure mode from post-hoc judge deductions into an in-session advisory.

## How it works

- `tools/post-execute` — read/write tool calls carrying a path mark the path as seen (writing a file obviously means the session produced its content).
- `agent/pre-step` — assistant messages assembled since the last scan are checked against the vocabulary; findings become notice messages folded into the step via `decision.messages` (the same delivery path doom-loop-guard uses; `agent.inject()` would queue into the next-step inbox and items queued inside a finishing turn are never claimed).

## Configuration (cordis.yml, plugin `config`)

| field | default | meaning |
|---|---|---|
| `enabled` | `true` | master switch |
| `reminderBudget` | `3` | notices per assistant message per turn |
| `cardCheck` | `true` | flag fabricated card IDs |
| `legacyCodeCheck` | `true` | flag 0.1.1-era error codes |
| `namespacedCodeCheck` | `false` | also flag namespaced codes outside the curated list (noisy) |
| `pathCheck` | `true` | flag cited paths never read/written this session |
| `readTools` / `writeTools` | discovery tools / edit tools | tool names that register paths |

## Vocabulary

`src/vocabulary.ts` is generated by `scripts/compile-vocabulary.mjs <path-to-dsh-plugin-upgrade-skill>` — re-run it after the upstream skill repo adds or renumbers cards. The legacy → namespaced code mapping is a curated copy of card `DSH-0.1.2-A2-02` and is deliberately a code constant, not parsed prose.

## Model Experience

### Advisory citation reminder

#### What the model sees

No tool schema or normal-call text is added. When an assembled assistant message trips a check, the next step receives one advisory user-message reminder per finding (`【cite-gate】…`): it names the fabricated card ID, the legacy error code, or the unread path, states the concrete consequence, and asks the model to verify the citation or mark the claim as unconfirmed (「待确认」).

#### Token effect

Zero tokens before a check trips. Each finding injects one fixed-length reminder — the text does not scale with answer length — bounded by `reminderBudget` per turn (default 3) and deduplicated per finding per turn.

#### KV Cache effect

Append-only; notices enter as new user messages after the reusable request prefix and do not invalidate existing KV-cache entries.

## Known Limitations and Deferred Work

- **Advisory only** — a finding does not block the message, rewrite the answer, or fail a verification; there is no enforcement mode.
- **The vocabulary is curated, not a complete API diff** — an ID's absence is evidence, not proof; a genuinely new card can draw a false reminder until the vocabulary is recompiled.
- **Reminders are budgeted, never escalating** — a finding fires once per turn no matter how often the model repeats the citation; repeat offenses draw nothing new.
- **Read-before-cite covers tool-mediated access only** — content produced through bash (heredocs, shell redirection) marks no path as seen unless the tool name joins `writeTools`.
- **The legacy-code map is a curated constant** — new upstream renames require recompiling the vocabulary or updating the constant (deferred: deriving the map from the skill corpus at compile time).
